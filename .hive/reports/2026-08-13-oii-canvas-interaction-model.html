Research brief · 2026-08-13 · M2 Canvas

该学 OiiOii 的不是“节点”，
而是对象旁边就能把事做完。

H3Storyboard 已经有更真实的无限画布和更严谨的生产协议；体验落差来自分镜卡几乎只读。改造目标不是复制另一个 node editor，而是让导演不离开画布就能检查输入、生成新 Take、看进度、播放结果并完成 QC。

建议拍板：P0 先闭合“选镜 → 预检 → 生成 → 进度 → 新 Take → QC”的单镜循环。OiiOii 的就地动作与媒体反馈可以搬；其结果覆盖分镜、全局日志槽和前端收到 URL 即视为成功的做法不能搬。

优先级改造 backlog

P0

分镜节点主动作：生成 / 新建 Take / 修复输入

一个主按钮，状态由服务端 preflight 决定；把 LOCK、MANIFEST、binding、TAKE_GATE 等稳定错误翻译成下一步，而不是 generic alert。

协议点：不改 shot_plan；create job 仍走 idempotency、compiled bindings、lock snapshot 和 representative gate。

2–3 天
P0

同视图 inspector

单击节点即展示 planned 摘要、binding 清单、最新 job 和 take 列表；复杂编辑复用 modal，保持卡片轻量。

协议点：planned 与 actual 分栏，pending/rejected 不使用批准视觉。

2–3 天
P0

卡内媒体 + Take switcher + lightbox

卡片明确显示 TAKE N 与 verdict；点击放大播放，同镜多 Take 可切换，不把“最新”误叫“最终”。

协议点：预览是 projection；actual、asset 和 QC 均保持独立记录。

2–3 天
P0

per-job 进度 capsule 与持久时间线

优先 snapshot polling；如增加流式端点，只流已持久化 job events。断流后重连/刷新仍能恢复真实状态。

协议点：DB-before-projection；不用 OiiOii 无 chunk buffer 的 parser，也不用全局单槽日志。

2–3 天

P0 验收线

  • 用户不离开画布即可完成：选镜、看缺项、提交、看进度、播放新 Take、QC。
  • 生成前后 shot_plan 不变，只 append job/asset/actual/event。
  • pending/rejected Take 不呈现为已批准；QC 与 representative approval 分别可见。
  • prompt 中出现的引用与实际上传、compiled binding 清单完全一致。
  • 刷新后任务与 Take 从 SQLite 恢复；断流不被误判为生成失败。
  • 真实 HTTP + SQLite 集成测试覆盖成功路径，以及 lock、binding、take gate 错误路径。
