P2.3 · AI 生成剧本基础闭环

日期：2026-08-28 · 生成主链：shuohao · 产品边界：drama creator-first + H3 人工批准

结论：P2.3 不再只是“导入剧本”。
Studio 现在提供 AI 生成剧本 与 导入已有剧本 两个并列入口；AI 结果须通过确定性门和 fresh-context 独立审阅，才保存为可编辑草稿，不能自动锁定、出分镜、批准或提交 4090。

上游判断纠正

shuohao-skills 确实有 AI 生成：宿主模型负责写 outline/script，Node 脚本负责 seed、校验和渲染。此前只接入 JSON 形态与校验，漏掉模型写作阶段，是实现偏差。

来源本次吸收不吸收
shuohao-skillsepisode/scene/flow 生成骨架；动作对白分离；时长、对白、钩子等确定性门TTS、声音报告、媒体生成链
drama-skillscreator brief；写作、独立审阅、创作者接受分权；verdict 与 evidence独立 Markdown 项目格式、声音标签

用户流程

创意 / 小说片段 / 梗概 → AI 生成 shuohao 结构 → 确定性质量门 → 最多一次自动修复 → fresh-context 独立审阅 → accepted draft ScriptVersion → 人工编辑/校验 → 锁定 → 分镜审核/批准 → H3
  • AI 输入：标题、故事材料、题材、目标时长、目标场景数、人物、气质、额外限制。
  • 导入输入：普通剧本文本或 shuohao novel-script JSON。
  • 审阅为新的无生成上下文请求；revise 不落库，approve(_with_notes) 连同 reviewer provenance 落库。
  • 两个入口之后共用同一套 Scene/Beat 编辑、版本链和 P2.2 审核。

硬门禁

  • 精确场景数；每场至少一个动作；对白说话人必须属于本场角色。
  • 单句对白 ≤35 个非空白字符；目标总时长按动作 2.5 秒/拍、对白 4.5 字/秒估算，容差 ±15%。
  • 每集开场钩子必须在本集前 3 拍内具象；episode/scene key 唯一；响应为严格 JSON。
  • 首轮失败仅修复一次；第二次失败或独立审阅拒绝均不产生草稿。
  • 已有 draft 或同项目已有生成进行中时，在再次调用模型前拒绝。

配置与安全

文字模型通过 OpenAI-compatible /chat/completions 接入。API 进程读取 H3_SCRIPT_AI_ENDPOINT、H3_SCRIPT_AI_MODEL 和可选 key/provider/timeout；密钥不返回 Studio。同一 endpoint 接收相互独立的生成请求和审阅请求；这里保证的是新请求/新上下文，不伪称是不同供应商。未配置时导入仍可用。

当前机器没有运行中的文字模型服务，也没有 OpenRouter/OpenAI/ApiMart 环境密钥；因此产品能力已接通并通过真实 HTTP provider 进程验证，但不能伪称已完成一次真实付费模型生成。

声音与生产边界

  • 系统提示词禁止 TTS、配音、音乐、环境声、雨声、音效和拟音字段。
  • AI 成功只写 draft；当前 locked script 和 active plan-set 不改变。
  • 不访问 ComfyUI，不创建 H3 Job；后续媒体仍只允许 H3 原生音频或静音。

验证

  • 真 HTTP provider → H3 API → 真 SQLite → 重启读取生成与审阅来源；P2.3 集成测试 25/25。
  • 错误路径：未配置、非 JSON、六类质量门、重复 key、多集晚钩子、HTTP/envelope/超大响应/body 超时、并发、已有 draft、独立审阅拒绝。
  • 真实 Chrome：双入口、模型状态、生成草稿、独立审阅、校验结果、版本来源、零 H3 Job；同时回归批准后审核台驻留与 100 镜请求预算。
  • pnpm check、pnpm build、pnpm test 全绿：48 个 Vitest 文件，305 passed / 1 个显式 live-ComfyUI skip；28 个 Chromium E2E passed。
