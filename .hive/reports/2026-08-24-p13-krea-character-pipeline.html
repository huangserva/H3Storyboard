P1.3 推荐用户流程

上传 / Krea 候选→人工批准 Master→Qwen / Krea 派生→候选对比→批准 + Freeze→H3 reference_character
  1. 母图候选：上传或 Krea2 T2I，一次按 seed family 出多张；全部只进入 candidate。
  2. 批准 master：用户检查脸、发型、体型、服装、配色；批准后才成为可用 CharacterReference。
  3. 身份编辑：换装、构图、多人物组合优先 Qwen identity edit，输入只允许 approved references。
  4. 轻派生：同场景姿态/景别用 Krea i2i；UI 明示 denoise，不做暗中自增或自动批准。
  5. 生成锁：只有 approved 且进入 frozen current-assets manifest 的图片能被 H3 编译为 reference_character。

不要复用 H3Job，建立 CharacterImageJob

当前 H3Job 的 mode 和输出语义都是视频，硬塞图片会污染协议。建议独立 job，但复用 H3 worker 已经验证的 submit-intent、同任务恢复、lease、原子 completion 方法。

错误与显存纪律

ERROR

稳定区分 input/capability/queue/GPU/HTTP/node/timeout/output；禁止只返回 false 后造 placeholder。

GPU LEASE

按 gpu_host 建共享 SQLite lease，让 Krea 8188 与 H3 8190 真正互斥。

OWN INSTANCE

只对配置为本项目所有的 endpoint 调 /free；绝不 kill ComfyUI 或他人任务。

  • 提交前同时查两端 queue/system stats；已有任务时返回 recoverable busy，不 free、不上传、不提交。
  • 旧规范写“约 17GB 空闲再开跑”，应改成 provider profile 的可配置门槛，并用真机数据校准。
  • 旧脚本会吞掉 /free 异常继续生成，生产实现必须 fail closed。
  • 取消只处理本 job 的 prompt id；不能全局 interrupt，更不能 kill 进程。

不进入 P1.3 的东西

  • 绝不接入任何 TTS、BGM、Foley、雨声、环境声或跨模型声音 fallback。
  • image provider 只依赖图像配置，只输出 image Asset；不能 import 视频音频配置。
  • 旧成品没有 prompt_id/request manifest，只能作为 legacy reference 导入，不能伪装成可重放 job。
