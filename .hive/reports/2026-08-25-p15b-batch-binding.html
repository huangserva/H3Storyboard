三条生产能力

BATCH
1–100 镜

项目、锁、Brief、Manifest、Mode、绑定和代表 Take 全部校验后，在一个 immediate SQLite transaction 内写入。

SEMANTIC DRAG
3 类来源

非归档图像、非归档角色、approved Take 的真实派生边界；目标和来源都按稳定 handle 解析。

RECOVERY
Exactly-once

响应丢失沿用原 idempotency key；不同 key 的同镜活跃 Job 被服务端拒绝，事务不会留下半批数据。

审查中修掉的真问题

  • 把 271 行的 use-studio 拆为生成 action、notice 和稳定批次 attempt cache；主 hook 回到 175 行。
  • 批量锁门禁在 store transaction 内强制，不依赖客户端 preflight；解锁直调 HTTP 会返回 LOCK_REQUIRED。
  • 服务端已提交但浏览器丢响应时，不再生成新 key；只有 project snapshot 刷新成功后才清除 attempt。
  • 不同客户端用不同 key 并发提交同一镜时，active-job guard 阻止重复活跃 Job。
  • continuity mode 改为从完整 dependency + role 集合派生，不受拖拽顺序影响；同一 asset 多 role 不再覆盖或误删依赖。
  • 归档角色、归档图像、归档边界不再暴露或被 API 接受；跨项目、pending Take、伪边界和自引用均拒绝。
  • 场景 rail 聚焦会清除旧批量选择；绑定期间禁用连线，成功快照带 project guard，避免切项目后的陈旧覆盖。
  • 百镜场景切换总是保存用户当前可见 viewport，关闭初始 fit 动画与用户 zoom 的恢复竞态。
  • 所有 shot production 路由参数统一安全解码；畸形 URI 稳定返回 400，不再成为 500。
