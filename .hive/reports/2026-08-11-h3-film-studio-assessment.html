一个 Claude skill：宿主 LLM 当导演（story → framework → storyboard 三层 JSON），Python 执行层落地（校验/参考图/生成/审查/合成）。fork 自 xyz-video-skill，把云端 Seedance 换成本地 H3（ComfyUI 8190）+ Krea2 图片（8188）。检视 commit 8693cc7。已验证：普通剧情片冒烟（turbo 4 步 ~80s / 124 帧 / 480×864 / 双流）+ 119s 叙事成片。

四条主借鉴线

1 · M1B adapter 蓝本 直接采纳

scripts/local_providers.py（314 行）就是工作的 ComfyUI 契约：POST /prompt 提交 graph → GET /history/{pid} 轮询 → 从 outputs 取 view URL 下载。含 i2v graph builder、LoRA 注入、seed 派生。M1B 的 adapter 不用从零猜，照这个契约写 TypeScript 版 + 补上 H3Storyboard 的 lease/恢复语义即可。

2 · 三模式映射被实证 直接采纳

xyz 的 video_references 用途协议天然映射 H3 三模式：first_frame→i2v、reference_character/prop/stage→r2v、reference_target_state→fl2v。这正是 M1A "语义引用需求编译成有序 binding" 的设计——现在有了实跑证据，照此定协议枚举。

3 · 角色一致性三重锚 回答 Q2

实证结论：角色 bible（逐字复述的外观描述）+ 空间锚 + 同 seed 族，缺一漂移；更强的锁是 Krea i2i 从角色主图派生（denoise 0.42）。→ H3Storyboard 的角色实体最小字段：规范外观文本（可逐字注入 prompt）、参考图集、seed 族、派生血缘。服装/造型状态机可后置。

4 · INTENT 协议 ≈ production brief 思想采纳

意图保全协议 = 文件化单一真相源 + 纠正即写（用户原话）+ 动手前必读 + 交付自检门。它是 M1A "版本化 production brief + 锁快照" 的文件版原型。H3Storyboard 把它升级为 DB 实体：brief 版本化、每个 job 固化锁快照、QC 门禁对照 brief。

该编译成协议校验的实证事实

实证事实（2026-08-09 实验）H3Storyboard 落点
宽高必须被 32 整除（854 报错，用 864）；帧数落 17k+5 网格（124）h3-provider 提交前校验，稳定错误码拒绝非法尺寸/帧数
H3 会把 prompt 里的中文 Audio 行整句念出来（包括"全程无人声"）；台词必须写在「」内并指明说话人；Audio 行只许英文或不写prompt 编译器 lint 规则：检测中文 Audio 行 → 阻断并报错，不靠文档自觉
H3 自带音频（video+audio 双流）；T8 采样 video_steps=4 / audio_steps=8，turbo 一刀切 4 步音频糊ShotActual 记录音频流存在性；QC 增加"听查"维度；采样参数入 Mode 能力表
Krea(8188) 与 H3(8190) 共享显存，切换前必须 POST /free，否则 OOMtask-engine 的 provider 切换钩子；worker 串行化图片/视频任务
偶发糊音是 seed 抽卡，同 prompt 换 seed 重跑即可显式 rerun 已在 M1B 计划内——rerun 原因枚举加 audio_garbled
母图派生多景别（一张高清母图 ffmpeg 裁切出全/中/特写）→ 视线、空间、光线天然连贯资产血缘支持"母图→裁切派生"关系；画布 UI 可按母图聚簇分镜卡片

不搬什么

  • skill 文档式流程本身 —— 无持久化、无 planned/actual 分离、pipeline 目前靠独立跑批脚本绕过（其待办自己承认）。这正是 H3Storyboard 存在的理由：给这套已验证的生成方法一个可恢复、可追溯的工作台。
  • 具体参数当常量 —— 480×864/24fps/turbo 4 步是当前盒子的验证点，进 Mode 能力表（candidate/validated），不硬编码。
  • 内容 profile 细节 —— profile 机制（不同 profile 覆盖不同 LoRA 栈与过滤开关）值得进 Mode registry 的能力维度；具体内容配置留在 skill 侧。
