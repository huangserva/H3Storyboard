Tooling assessment · 2026-08-11

r2v 质量差是权重问题，
这个节点是现成解药。

MiniMax 官方两个 H3 checkpoint：fl2va 质量高但只有首尾帧条件，ref2va 有多模态参考条件但训练有质量缺陷。这个 MIT 许可的 ComfyUI 节点用逐 tensor 分析证明两者 97% 权重一致，分歧集中在模态调制投影（adaln_proj），并提供"fl2va 底座 + ref2va 参考通路"的混合加载。

结论：对 M1B 直接有帮助。GPU 盒装上此节点后，r2v 模式可获得 fl2va 级画质 + 参考条件能力（作者推荐 preset：block_range_adaln，blocks 30–49）。把它作为 r2v-hybrid candidate Mode 录入 registry，M1B 实施期做同 prompt/seed 三方对照后升 validated——正好首跑 M1A 的能力验证状态机。

为什么这事关键

事实对 H3Storyboard 的意义
ref2va 有官方确认的训练质量问题；fl2va 质量明显更高解释 r2v 出片差的根因；h3-film-studio 待办"打开 r2v"不必硬扛原生 ref2va 质量
932 tensors 逐一对比：97% 一致，分歧集中在 adaln_proj.linear.*（cosine 负相关）参考通路结构在两模型中都在（token_refiner/condition_proj 几乎相同）；只需叠加调制投影即可恢复参考能力
混合加载 = fl2va base + ref2va 的 blocks 30–49 adaln_proj overlayprovider 的 r2v graph 换 loader 节点即可，i2v/fl2v graph 不受影响
mmap 流式合并，峰值内存 ≈ 单模型（19.5GB int8），只读，量化感知GPU 盒可直接用，不加剧 Krea/H3 共享显存的紧张局面
MIT 许可，单文件 552 行，行为与 stock loader 兼容部署为 GPU 盒 custom node 即可，无需并入本仓库

落地路径（M1B 实施期）

  1. GPU 盒 ComfyUI/custom_nodes/ 部署本节点，确认 fl2va / ref2va 两 checkpoint 就位（各 ~19.5GB）
  2. Mode registry 录入 r2v-hybrid（candidate），capability 声明 loader preset + block range 参数
  3. 对照实验：同 prompt/seed 三方出片（纯 fl2va / 纯 ref2va / hybrid），QC 裁定后升 validated
  4. provider r2v graph builder 切换 loader 节点（参照 h3-film-studio 的 graph 构建方式）
