P2.1 DELIVERY · 2026-08-26

Script Studio 已形成第一条可测试生产入口

H3Storyboard 现在能把普通剧本文本或唯一选定的 shuohao novel-script JSON，变成可编辑、可校验、可锁定、可追溯的 Scene/Beat 文档，并编译成画布里的草稿 ShotPlan。到此为止不会触碰 4090。

结论：P2.1 完成，可以进入人工画布测试。
它不是 AI 自动写作，也不会自动出片；它先补齐可信的剧本数据、版本和审核边界，为 P2.2 导演审阅/批准打底。

交付能力

plain text / shuohao JSON → draft ScriptVersion → Scene / Beat 编辑 → validate → human lock → deterministic compile → DRAFT ShotPlan → canvas
结构化剧本动作/对白分型；角色、语气、时长、服装、位置、道具均为持久字段。
版本与并发draft/locked/superseded；revision + expected_revision 阻止双标签静默覆盖，历史版本可点选。
安全编译4–15 秒确定性分组；每个 Plan 保存 Scene/Beat/Compilation 来源，sound 恒空。

协议与数据

层结果
Protocol 2.0新增 ScriptDocument、Scene、Beat、Validation、Lock、Compilation；ShotPlan 新增 planning_status 与来源/状态字段。
SQLite v24新增 script_scenes、script_beats、script_compilations；版本 revision、唯一 draft/compilation、Plan provenance。
API7 个 script endpoints：list/import/get/update/validate/lock/compile，全部 snake_case、稳定错误码。
Studio版本栏可选择历史和建立后继；Scene/Beat 编辑、校验结果、锁定、编译后自动回画布。

硬门禁

  • 编译 Plan 一律为 planning_status=draft。
  • 真实 HTTP 已验证单镜 POST jobs 和 batch POST 都返回 SHOT_PLAN_DRAFT，数据库保持零 Job。
  • 旧 Script/Plan/Job/Take 不被覆盖；superseded Script 使用原 key 仍可回读原 Compilation。
  • Script Studio 不调用 ComfyUI；不创建 TTS、配音、音乐、雨声、环境声、SFX；Plan sound=""。
