H3Storyboard 剧本与提示词上游评估

对 6 个候选仓库做了源码、协议、许可证和自测核查，并对照 H3Storyboard Protocol 1.9。核心判断：应补一套原生的 Script Studio，但不应把小说 IDE、短剧 skill 或通用 Prompt 产品直接合并进 H3Storyboard。

有用
优先吸收 `shuohao-skills` 的结构化剧本与确定性质量门，再吸收 `drama-skills` 的创作者体验和阶段边界。
H3Storyboard 自己拥有持久化协议、版本、审核、Scene/Beat 到 ShotPlan 的编译关系；外部仓库只作为方法和可许可实现的参考。

一、H3Storyboard 的真实缺口

有 ScriptVersion 表title/content/status 已存在，状态枚举也有 draft/locked/superseded。
但产品只会锁定新建项目必须粘贴至少 20 字，API 在同一事务里直接创建并锁定 Script V1，没有草稿编辑、版本历史或 diff。
没有剧本工作流没有点子/小说导入、故事开发、场景与节拍结构、角色抽取、时长/覆盖校验，也没有剧本到 ShotPlan 的编译器。

所以“项目没有做剧本部分”这个判断是正确的。现在的 ScriptVersion 是一个生产输入封套，不是创作系统；ShotPlan.scene_id 仍只是字符串，也没有可追溯到具体剧本节拍的来源关系。

三、推荐产品边界：P2 Script Studio

H3Storyboard 不应变成“写 200 万字小说的 IDE”，而应成为从创作材料到可生成镜头的导演工作台：

点子 / 小说 / 现成剧本
→
版本化剧本
Scene + Beat
→
资产与连续性抽取
→
草稿 ShotPlan
人工锁定

P2.0 · 剧本内核

  • 让项目先创建 draft ScriptVersion；支持导入现成剧本、编辑、锁定、新建后继版本、diff 与 supersede。
  • 新增结构化 ScriptScene 和 ScriptBeat：动作、对白、转场、画面文字分开；对白保存 speaker、line、delivery。
  • 每次锁定生成不可变版本；已存在的 ShotPlan / Job / Take 不随剧本修改而变。

P2.1 · AI 剧本工作流

  • 入口支持：一句话、故事大纲、小说/长文、现成剧本；材料足够时允许跳过上游阶段。
  • AI 负责内容，代码负责门禁：时长预算、对白长度、角色合法性、场景/道具对账、每场可见动作、跨场状态连续。
  • 长篇材料只引入按需检索和事实摘要，不把 webnovel-writer 的整套 RAG 系统装进核心。

P2.2 · 剧本编译成分镜

  • 新增来源映射：每个 ShotPlan 记录对应 Scene 与 Beat 区间，做到原文覆盖、不重不漏。
  • 编译只创建“草稿镜头”；导演确认后锁定，再进入现有角色参考、H3 Job、Take/QC 和 M3 batch。
  • 剧本改版产生新镜头集合和差异清单，绝不改写旧生成历史。

P2.3 · Prompt Recipe 与评测

  • 把提示词作为版本化 Recipe：task/provider/model/version/template/constraints，而不是散落的“万能 prompt 库”。
  • 视频 Recipe 由 H3 binding、镜头起止状态、角色/场景参考和时间点确定性编译。
  • 角色/场景静帧可以引入 provider-neutral 风格标签；实际 prompt 由当前图像 provider adapter 编译。
  • 评测以代表图/代表 Take 对比为中心，不再造一个通用 Prompt Optimizer 产品。

四、必须守住的边界

  1. Plan / Take 不合并：剧本、分镜计划、H3 Job、实际 Take 继续分别持久化。
  2. 声音不回退：外部 skill 中的 TTS、配音、BGM、soundscape、SFX 和音频参考全部不迁；仍只允许 H3 原生声音或静音。
  3. 许可证隔离：Apache/MIT 可在保留许可与 NOTICE 的前提下评估代码复用；GPL、AGPL、无许可证仓库只借思想，不复制实现或模板。
  4. 不把 Markdown 当数据库：可以提供创作者友好的 Markdown 导入/导出，但 SQLite + protocol 仍是唯一真相。
  5. 不直接生成：AI 剧本和自动分镜必须经过显式锁定，不能从一句话直接越过审核提交到 4090。

五、优先级裁决

建议先做 P2.0 + P2.1，再继续 M3B。原因是 M3B 扩大的是视频参考模式覆盖，而 Script Studio 补的是产品入口；没有剧本上游，H3Storyboard 仍要求用户在别处完成最核心的创作，然后手工粘贴和逐镜录入。

最小可测试交付应是：创建空项目 → 写/导入 draft 剧本 → AI 或人工拆成 Scene/Beat → 质量门 → 锁定 Script V1 → 一键生成可审阅的草稿 ShotPlan。到这一步才算补上剧本能力，不需要在第一版实现长篇 RAG、TTS、音乐或全自动出片。
